## What the action does now

- `action.yml`, check mode, three steps:
  1. **Run KAERIS** runs `kaeris check` (always with `--sarif`, to `$RUNNER_TEMP` unless
     `sarif-file` is set) and summarize.py. **No GitHub token in its env.** It exits 0 in
     check mode and hands the JSON path, SARIF path and exit code on via `$GITHUB_OUTPUT`.
  2. **PR comment** (`if: inputs.mode == 'check'`) runs `pr_comment.py`. Only this step gets
     `github-token`. It always exits 0 (plus `|| echo ::warning::` for a crash).
  3. **Gate on kaeris check** exits with the CLI's code, the same as v2.1.0.
- New inputs: `comment` (default `true`), `comment-key`, `comment-author`, `github-token`
  (default `${{ github.token }}`), `cta` (default `true`, also drives the summary's link).
  New output: `comment-url`. Existing inputs, outputs and exit codes are unchanged.
- `pr_comment.py` (stdlib):
  - the marker is a hash of source + out + sorted languages (or `comment-key`);
  - a comment is ours only if it starts with the marker AND its author is `comment-author`
    (default `github-actions[bot]`, type Bot);
  - PATCH, else POST, then a re-read: newer duplicates of ours are deleted and the oldest
    stays (OS-matrix race); if the PATCH gets 404 it falls back to POST;
  - "fails" follows the CLI's exit code, and `strict` is the exact string `"true"`, the same
    test as in bash;
  - a language with no locale file is one row, listed first;
  - `pull_request` only;
  - stdout and files are UTF-8 explicitly.
- `README.md`: "Findings in a PR comment", `permissions` + `concurrency` in the example, the
  new inputs, a fork PR = no comment (findings in the job summary), why not
  `pull_request_target`, changing source/out/languages leaves the old comment.

## Decisions

- **`comment` defaults to `true`.** The feature is worth something only if a user of `@v2`
  sees it without reading a changelog. It cannot break a v2 workflow: exit codes are the same,
  no comment on a clean PR, and without `pull-requests: write` there is one warning only on a
  failing run. `comment: false` turns it off.
- **`comment-author` instead of `GET /user`.** With the default GITHUB_TOKEN `GET /user` is
  403, so it would work only for a PAT and cost a call per run. One input with the right
  default covers both.
- **Created only when the check failed** (by the CLI's exit code). `kaeris check` looks at
  the whole locale, not the diff: a repo with old warnings would get a comment on every PR.
- **Matrix duplicates: delete the newer, keep the oldest.** Needs the same permission as
  posting; if the delete fails the duplicate stays, nothing else breaks.
- **Link `?utm_source=action-comment`, not `?ref=`.** The site reads the source of a visit
  only from `utm_source`.
- **`pull_request` only.** Not `pull_request_target` (base checkout, pwn request).

## Open (for v2.2.0 and later)

1. Moving the `v2` tag to v2.2.0 turns the comment on for every `@v2` user: the director's
   call, plus a line in the release notes.
2. Not done now, by the critic's list: pagination by the `Link` header (we page by count, up
   to 1000 comments); links to the head commit vs the merge commit (we link `head.sha`, which
   is what the reviewer sees in "Files changed"); phantom rows from `.xcstrings` catalogs.
3. Line numbers only for JSON/ARB; other formats link to the file without a line.
4. Exit 2 (bad usage, no JSON) leaves an existing comment as it is; the job is red with the
   error.
5. This repo's own `test.yml` check jobs on a PR have `contents: read`: the broken job will log
   one warning. Either `comment: false` there or `pull-requests: write` in `check-broken` to
   exercise the comment live.
6. Live e2e on a private repo: `docs/P22-E2E.md`, `docs/p22-e2e/i18n-check.yml`.
