# P2.2 live check: the PR comment on real GitHub

Prepared, not run. Creating the repo, tags and the Marketplace release is the director's call.
Branch under test: `kaeris-io/kaeris-action@p22-pr-comment`. About 15 minutes.

## 0. A private repo

1. New **private** repo, e.g. `kaeris-io/e2e-pr-comment` (private on purpose: no Code
   Security, so SARIF would show nothing there and the comment is the only place findings land).
2. Settings > Actions > General > Workflow permissions: leave the default ("Read repository
   contents"). The workflow asks for `pull-requests: write` itself; this proves it is enough.
3. On `main` commit three files:

   `locales/en.json`
   ```json
   {
     "greeting": "Hello, {name}!",
     "checkout": { "title": "Checkout", "pay": "Pay {amount}" }
   }
   ```
   `locales/de.json`
   ```json
   {
     "greeting": "Hallo, {name}!",
     "checkout": { "title": "Kasse", "pay": "{amount} bezahlen" }
   }
   ```
   `locales/fr.json`
   ```json
   {
     "greeting": "Bonjour, {name} !",
     "checkout": { "title": "Paiement", "pay": "Payer {amount}" }
   }
   ```
   and `.github/workflows/i18n-check.yml` = `docs/p22-e2e/i18n-check.yml` from this branch.

## 1. Broken `{name}`: comment + red job

Branch `broken`, in `locales/de.json` change `{name}` to `{nam}`, open a PR.

Expect:
- [ ] job **i18n check / check** is red (failure), `check-exit-code=1`;
- [ ] exactly **one** comment from `github-actions[bot]`, title
      `KAERIS i18n check: 1 problem to fix`, row `locales/de.json:2 | greeting | de |
      lost placeholder {name}; invented placeholder {nam} (not in source)`;
- [ ] the file cell opens `locales/de.json` at line 2 on the PR's head commit;
- [ ] "job summary" opens the run; the summary has "Findings (1)";
- [ ] `comment-url` in the last step's log is that comment.

## 2. Second push, still broken: the same comment is edited

On the same branch also delete `"title": "Kasse",` from `locales/de.json`, push.

Expect:
- [ ] still **one** KAERIS comment (no second one); its header now says `2 problems to fix`
      and it lists `checkout.title | de | missing in this language`;
- [ ] the comment shows "edited"; the job is red.

## 3. Clean push: the comment says so, the job is green

Put `{name}` and `"title": "Kasse"` back, push.

Expect:
- [ ] job green (success);
- [ ] the same comment now reads `KAERIS i18n check: no problems`, `nothing to fix any more`;
      still one comment.

## 4. A clean PR from scratch: no comment

New branch from `main`, change only `fr.json` text (`"Paiement"` to `"Caisse"`), open a PR.

Expect:
- [ ] green job, **no** KAERIS comment at all.

## 5. No permission: warning, verdict unchanged

On the PR from step 1 (re-break `{name}` if it is clean), remove the `pull-requests: write`
line from the workflow in that branch, push.

Expect:
- [ ] job red because of the finding, not because of the comment;
- [ ] one annotation `KAERIS PR comment: Could not ... (HTTP 403 ...) Give the job
      permissions: pull-requests: write ...`;
- [ ] the old comment is not touched.

Then fix the placeholder (still without the permission), push: green job, no warning.

## 6. Not a PR

Add `push:` to `on:` and push to `main`: the job runs, no API call about comments (no
"KAERIS PR comment" line in the log).

## Record

For each step: run URL, screenshot of the comment, pass/fail. Paste into `docs/P22-RESULT.md`
under "Live e2e". Then delete the e2e repo or keep it private as a regression fixture.
